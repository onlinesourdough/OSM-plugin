# User-owned continuation or whole-task transfer

Use only for a selected/requested portable brief or whole-task transfer under the
[shared task-result decision](lifecycle.md). That lifecycle owns continuation;
[Model advice](model-advice.md) supplies model/reasoning evidence.
Orchestrate Workers applies only when the caller retains coordination and acceptance.

## Choose proportionately

Respect existing instructions and preferences. Continue autonomously where the
next action is clear and authorized; do not ask again for settled authority.
A new task may be worthwhile when its sufficient route reduces expected total
cost and the current lead adds no continuing value. A cheaper model alone does
not prove this. Preserve context when transfer would repeat substantial work.

The user can own the next step: read the Spec, use a website or ordinary tool,
copy a prompt into another assistant (for example ChatGPT or Gemini), or ask for launch later. Preparing
this brief requires no provider access. Recommend a model/effort only where
current evidence supports it; otherwise state needed capabilities and unknown
availability. Do not invent account access, equivalent effort labels or savings.

If a material tradeoff cannot be resolved from available evidence, give the
recommendation, its uncertainty, a ready prompt and one concrete question.
Pause the dependent route; avoid speculative build or repeated lead analysis.
No question is needed when the user simply requested the portable brief.

For a research report, prepare the question, boundaries, source standards and
deliverable. For file analysis, prepare the file list, relevant structure,
definitions, questions and checks. For a newsletter, prepare audience, purpose,
accepted material, voice and editorial constraints. These are examples, not
fixed routes: perform only enough inspection/clarification to make the brief
usable. Do not research the full report, analyze the whole dataset or draft the
issue before deciding who will do that production. Specialist guidance may help
Spec; full specialist invocation follows only when production is selected here.
Explicit requests to execute here remain valid; preparation-only is not universal.
Another product's subscription does not prove zero token use or zero marginal cost.

## Deliver a usable prompt

Provide one copyable prompt or accessible artifact with:

- the outcome, accepted Spec and decisions, relevant source facts and content;
- remaining judgment, allowed discretion, constraints, exclusions and authority;
- the requested next work, quality bar, checks, required Review and delivery;
- essential files/assets, access requirements, unresolved facts and next action.

Use the already accepted specialist outputs; do not repeat discovery. Include
essential instructions, not only local skill names, private paths or links the
recipient cannot read. For repository execution, carry repository/root identity,
applicable local lifecycle, current changes and one-writer boundary. Rebind actual
paths and discover tools at the destination before mutation. For chat-only work,
omit repository ceremony. Name missing attachments; never claim they transferred.
Include only relevant authorized context, no unrelated owner memory or credentials.
The recipient must retain any required independent Review and action approvals;
transfer does not turn unfinished work into acceptance.

## Make the handoff easy to use

Return a short reason and a direct destination link, then one fenced, copyable
prompt containing everything the recipient needs. Put required file links or
attachment names beside it, with one clear next action: open, paste, attach and
start. Use a native copy/download affordance when available; never claim the
clipboard changed without proof. A long brief may be a linked complete artifact,
with a short copyable starter that explicitly tells the user to attach it.

Use a known working destination or a verified native task link. A documented,
supported prefilled link is optional; never invent URL parameters or imply that
an ordinary homepage link starts work, selects a model or transfers attachments.
If destination access is unknown, give the normal entry link when known and
name that gap. Avoid making the user reconstruct the task from this conversation.

## Optional direct launch

Launch only within actual native rules and existing user authority. For Codex
create_thread, require an explicit request for a new task; a standing conditional
request counts only if it explicitly covers this work and the tool permits it.
Omit model unless the user explicitly requested that model. A skill's suggested
model is not that request. Honor supported requested effort. If omission would
defeat the proposed cheaper route, resolve that choice before launch rather than
silently launching another expensive lead. No automatic config or account change.

Use a supported new-task control with the prepared prompt and correct destination.
Transfer accepted scope, statuses, existing goal identity/authority and pending
Review/delivery; do not create a replacement goal without native authority.
If a goal/automation would keep waking this lead, verify supported transfer or
stop under existing authority. Missing control needs the exact user action;
do not promise the lead has stopped or mark unfinished goals complete.
Stop overlapping production before launch. Verify readiness and prompt acceptance
from returned state or a bounded startup check. Queued setup alone proves only
queued setup. On failure or uncertainty, report the actual state and provide the
prompt; do not blindly retry and risk duplicate writers.

Once startup is confirmed, return the actual task link/handle and end this lead's
work. No routine monitoring, extra review, automation or archive follows unless
requested or retained in the contract; such a retained coordination role instead
selects orchestration. A manual handoff ends with the prompt and exact next step.
Mark only the handoff complete; keep unfinished outcome obligations visible at
their new owner. Do not claim delivery, token savings or task completion from launch.
