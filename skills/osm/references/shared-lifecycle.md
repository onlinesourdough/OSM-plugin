# Retire legacy OSM phase copies from selected repositories

Use only for an authorized migration of named Systems/Projects or their seeds.
Package installation alone does not authorize repository writes. Inspect local
AGENTS, branch, dirty state, active work and current callers first.

OSM no longer supplies generic Spec, Build, Review, Ship, technology choice,
repository audit or tracking methods. The repository and its native harness own
engineering. Inventory each candidate's contents and ownership. A copied or
wrapped OSM/AIOS phase body, or a caller of a retired OSM skill name, is a
migration candidate. A design review, content graph audit or other domain
method may be correctly specialist-owned despite a similar name; preserve it.

Capture exact base commits and recoverable bytes for overlapping local changes.
Move actual repository-specific requirements from an old copy to AGENTS or their
existing domain source. Point callers to the repository's own or native method,
or to [Council](../../osm-council/SKILL.md) for an independent review, never to
cache paths, wrappers, symlinks or a retired OSM name. Remove a copied body only
when the owner accepts that replacement. Check links, specialist preservation
and the repository's affected validations. Template generators must emit local
contracts and specialist space without OSM phase copies.

Use isolated reviewable commits. An active or dirty checkout needs explicit
scoped reconciliation: precompute the merged instruction changes, preserve
unrelated bytes and reject concurrent drift or ambiguous conflicts. Never stash,
reset, clean or publish unrelated work to make adoption pass. If safe local
adoption cannot be verified, retain the reviewed commit and report the pending
root; package success is not repository migration proof.

At the task boundary, verify installed OSM identity and fresh repository
discovery. Loaded sessions may retain old instructions until a fresh context;
report that separately. Record base/new commits, preserved specialists, checks
and remaining gaps. Git can recover tracked removed methods; it cannot restore
untracked artifacts that were not separately preserved.
