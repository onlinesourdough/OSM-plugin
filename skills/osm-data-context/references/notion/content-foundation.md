# Content foundation

Core Setup owns the store binding and minimum schema. The optional
[OSM Content method](https://github.com/onlinesourdough/OSM-Content) owns adapted
editorial methods, workflow states, views and production guidance. Installing
either package alone creates no data and installs no personal Content methods.

## Resolve once during authorised setup

Include Content in the short new-home setup plan. Inspect the owner's actual
workflow and grants before proposing a destination. If there is no suitable
owner, propose **one empty Content database**, with no sample records, as part
of that concrete plan. Existing setup authority covers the described creation;
ask only if authority or a material choice is missing. The owner can defer.

An unanswered proposal is not an owner decision. Record `deferred` only from
the owner's actual choice, with its evidence and activation condition; never
turn the agent's suggestion to wait into that choice. An unresolved selection
stays an explicit setup gap, with no invented outcome or destination. Continue
independent authorised work without silently creating a competing store.

Resolve exactly one outcome; ambiguous ownership creates nothing:

| Outcome | Record and do |
| --- | --- |
| Existing Notion | Verify the account, database/data-source IDs, actual field equivalents and existing workflow; reuse them without migration. |
| External | Keep the authoritative editor, CMS or other system. Record its selected account, reader, permitted operations, retention and trigger dependencies. Create no parallel Notion Content database. |
| Deferred | Save the choice and its actual activation condition, or "when requested". Do not create a database or ask again on normal resume. |
| New Notion | Within the accepted setup plan and write scope, create one empty database with the minimum fields below. Save its exact identity before adding relations. |

An established home without Content is valid. Normal resume, Prime, Log,
Dreaming, installing an update or selecting a Content template does not activate
this proposal or retrofit that home. Reopen a recorded deferral only when its
condition is met or the owner requests it. A changed or ambiguous route is a
reconciliation task, not permission to create a replacement.

## One binding in the definition

Keep the outcome in the existing definition or its linked source agreement,
not in a second editable field map. Record the evidence for the choice, exact
account and scope, authoritative system, selected reader, allowed actions and
retention. For Notion, include both database and data-source identities and
the useful field equivalents; `destinations.content` points only to a selected
Notion store. For an external outcome, the definition's sources or linked
source agreement names the actual system; there is no local Content destination.
Deferred has neither invented IDs nor
an unverified reader. Unknown information stays an explicit gap.

Inspect automation, integrations and publication triggers before writes to an
existing store. Record the actual trigger-sensitive fields/actions and a
verified non-publishing write path, or the precise unknown. A trigger is not
limited to a Status field. An unknown trigger holds only the dependent writes;
independent reads and other authorised work can continue. A writable database
does not authorise publishing, sending or starting an editorial workflow.

## Minimum schema for a new empty Notion store

Define this minimum here once; optional Content configuration references the
binding and adds only the chosen editorial fields. Existing sufficient native
equivalents are valid; do not add synonyms, change types or overwrite workflows.

The Notion-authored [database field definitions](../../assets/database-fields.md)
are the single field/type list. For a new Content store they specify Title,
Key, Type, an empty Status, Summary, Source URL, Source date and two
self-relations. Do not copy another schema from a personal method.

Create the database with non-relation properties, then verify and record its
database/data-source IDs in the selected definition. Add the two self-relations
against that exact data source using supported tools, and read back their
targets and types. If interrupted, rediscover those same identities and add
only missing properties. A response with an uncertain result requires readback
before retry. Where a tool cannot create an empty select or self-relation,
retain the verified destination and report the remaining field step; never
substitute a fake status, text relation, second database or sample record.

Source, Content and Edition are useful roles, not a required funnel. A short
original can stand alone. Knowledge owns lasting business direction, audience,
offers and voice. Content owns material or references selected for production,
actual originals and editions; a brief remains a plan rather than finished
material. Memory owns a genuine lasting decision, not every production event.
Live media and source-only originals stay in their owning systems. For
source-only material, keep only its permitted route; never copy its body,
summary or sensitive facts into a record, log or worker brief. A transcript
does not relax the original handling rule. Other retained references and
meaning require that source's actual permission. Duplicate capture reuses the
existing item.

## Reuse through the optional methods

Before any selected personal Content method creates a destination, read this
binding and inspect the actual schema. Reuse the registered route and IDs,
including an interrupted or empty setup. Frozen older Content setup templates
are not authority to create another collection or supersede core's current
route, retention or trigger contract. Keep those packets' actual versions and
bytes; adapt a personal method explicitly rather than rewriting the packet.
The optional method owns selected workflow details, not another store map.

Report structure and useful-work proof separately. An empty store with verified
types and relations may be structurally ready with the content path unexercised.
No fake post, personal skill, publication, newsletter subscription or scheduled
caller is required to finish this foundation step. Unchanged replay writes
nothing.
