# OSM:setup

Own onboarding through a verified home, pointer and first task. Reuse answers.

Codex **Set up** or an explicit request starts this skill. Resume accepted
setup and connections. Verify access; a badge or saved link is not readiness.
Register verified personal sources using the [panel](references/panel.md) procedure.

For package installation or a requested bridge-only change, use the
[adapter route](references/adapters.md); preserve the existing home. Installation
alone needs no home creation or global instruction edit.

[Context](../osm-context/SKILL.md) owns the home contract. Use its
[provider selection](../osm-context/references/providers.md) only if unresolved.
Carry the choice forward: [Notion setup](../osm-context/references/notion/setup.md),
[existing-home adaptation](../osm-context/references/existing-home.md), or the
managed AIOS file procedure below. An Obsidian vault is not that file format.

## File-home setup

Follow [setup](references/setup.md) for questions, conditional Interview and
readiness. Resume stays scoped.
For personal skills during setup or a home move, call Manage Skills'
[personal skill lifecycle](../osm-manage-skills/references/owner-skills.md).
When an owner asks in ordinary language for local guardrails during autonomous
use, route that request to [Manage Skills](../osm-manage-skills/SKILL.md). It
owns candidate review/acquisition and its evidence. Normal setup does not
depend on an optional guard implementation.
For an existing folder, read [data compatibility](references/data-format.md)
before writing; an actual import also uses the [migration procedure](references/data.md)
and [identity migration](references/migration.md) for current AIOS, legacy OSM 0.1.x,
template AIOS and discovery collisions. Blank owner assets are in [assets/owner](assets/owner/AIOS.md).

Resolve the established/requested home or bridge to its physical absolute path.
Only without either, inspect ~/.AIOS; create there only under new-home intent.
An absent default never justifies a second home.

For a missing/empty home with unresolved new/restore intent, ask one friendly choice:
“Sync the existing home or set up new?” An established, partial or custom-root home
resumes without that question or a repeat interview. Finish a new home or move
with the explicit [Sync](../osm-maintain-context/references/sync.md) continuity
choice; Sync remains the one procedure for remote, direction and scope consent.

Start setup for a new/incomplete home only without a competing task. Never
interrupt unrelated work, restart established setup or infer install authority.

Use Maintain Context for source routes and minimal gap filling. On a move,
verify source access in the receiving account.

Requested persistent routing uses the harness's thin optional bridge; never
add owner-home AGENTS.md that preloads nested repositories.
Create owner files from the supplied neutral assets with ordinary file tools,
never clone AIOS-template. Keep product version and data format separate.
Local operation works without Git. Do not install anything or change global
settings unless the current task authorizes it. Preserve unrelated instructions,
secrets and configuration keys. For new or
changed setup, run the relevant [setup acceptance](../osm-check/references/setup-scenarios.md)
checks and report unavailable proof; an unchanged resume needs only its task checks.
