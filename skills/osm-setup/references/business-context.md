# Enough context for useful work

Use during business onboarding or a requested foundation audit, not as a daily
preload. Inspect the selected sources and reuse accepted answers. The
[business lenses](../../osm-interview/references/owner-context.md) help find gaps:

| Area | What the agent should be able to find when relevant |
| --- | --- |
| Offers | What is offered, to whom, the promised result, scope and commercial boundaries |
| Demand | Audience, positioning, brand/voice, channels and actual evidence of demand |
| Operations | How work is delivered, responsibilities, constraints, systems and review points |

These are coverage questions, not required folders, new properties or three
documents per Space. A source may cover several areas. A Space says which
business or brand the information applies to; it is not a business topic.

Map each area to a verified source or an explicit gap in the setup handoff.
Resolve only gaps that affect the selected task; others can remain pending or
not applicable with a reason. An accessible page or a Current label is not proof
of adequate content. Ask concrete questions from observed work, such as which
offer is current or who approves a price. Never complete the map with assumptions.

Docs holds facts and links to maintained sources. Skills holds repeatable ways
to use them. Inspect existing SOPs, checklists and useful prompts with the owner;
adapt selected personal methods through Manage Skills, preserving references.
Do not copy shared plugin methods or project skills into personal Skills, or
invent a skill for every area. Working principles are optional owner preferences
or real constraints, not a default philosophy to generate for every customer.

Memory may start empty. Import only selected genuine prior decisions with their
reasons and provenance; preserve existing memory. During work, reconcile useful
decisions and corrections with their owning record. Do not duplicate ordinary
facts into Memory or add a record just to demonstrate activity.

For the first task, verify the needed facts, selected method if any, accessible
source routes, intended output, reviewer and write boundary. Record missing
access separately from missing knowledge. Connect only sources the task needs;
credentials stay outside context. Keep one concise source map in the existing
entry/handoff, not another company inventory. Return structural readiness,
first-task proof and any still-pending correction test separately.
