# Codex setup and dashboard

The normal Notion flow is: connect Notion, select the AI Operating Model, review
its overview in the panel, then press **Save pointer**. Reviewing or refreshing
the overview never writes Codex instructions. Only Save pointer, the Context
step's Save pointer button or a confirmed Settings context switch writes the
managed context block (AIOS markers), with the existing backup and revision checks.

The panel cannot read Notion pages itself. When the person selects a model or
asks to refresh its overview, read the model through the existing Notion
connection in chat and register a dated snapshot with Context's
[overview procedure](../../osm-context/references/panel-links.md#operating-model-overview).
Ask them to refresh the panel. After a route change in the model, refresh the
overview the same way.

The dashboard leads with navigation: the model's own title with Open in Notion,
then a card for each of its source sections, with the model's own headings and
exact links. The main view shows only what needs action: a hidden, failed or
held overview, a section choice, or Save pointer. When links may be incomplete
or completeness is unknown, one line says "Some links may be missing" with a
Details button. Connection, host pointer, the source revision, the snapshot's
save time, coverage and why rows were left out sit in the closed **About this
overview** disclosure. None of these shows that a running agent has loaded the
model, that a skill is enabled or discoverable, or that Memory exists. If
sections are ambiguous, show the listed sections and let the person choose
once; do not re-pick destinations or rewrite the model.

Earlier Docs, Skills and Memory links appear below the cards as **More links**,
with their values and Settings editing; a saved link to exactly the same
destination as a card is not repeated, and new setups add none. Without an
overview, and for folder contexts, the four sections (Notion, Context, Skills,
Memory) work as before. Panel buttons never start a chat or agent.

OSM and the Notion connection remain separate. Native status checks
installation, enablement and connection; Connected does not prove page access,
callable discovery tools or a complete business setup. Library enablement and
sharing stay in Notion. Page selectors fetch names and navigation metadata only.

For requested business onboarding, verify the home, reuse existing sources,
preserve Spaces and access, and prove a useful task. A consultant's client task
never changes their personal default, its overview or its links. Labels grant
no access. The panel stores names, links and the derived overview only; company
information stays in its source and the model in Notion stays canonical.
Earlier saves remain after a later failure. Stale edits keep their draft and
require reconciliation; they must never silently adopt a new revision.
