# Native adapter route

Install only in the selected harness under the task's existing authority.
Its native package manager owns installation, update and removal. All adapters
use the same skills; installation creates no owner home, global instruction
block, cross-harness registration or discovery filter. Preserve unrelated
skills, settings, overrides and credentials. No background service is needed.

Read exactly one operation route:

- [Codex](adapter-codex.md) for its package or optional bridge;
- [Codex desktop](adapter-codex-desktop.md) only for affected New Chat or workspace state;
- [Pi](adapter-pi.md) for its package or discovery;
- [Claude Code and Copilot](adapter-claude.md) for their native plugins;
- [Gemini, Cursor and other harnesses](adapter-other.md) for those routes;
- [package lifecycle](adapter-portability.md) for cross-harness adoption, update or removal.

Select [harness configuration](harness-configuration.md) only for a concrete
settings, precedence or capability need. Package registration proves neither
model behavior nor owner setup.

## Optional owner routing

Resolve provider and owner/client scope. Client setup uses task guidance or a
verified client-only instruction scope; preserve the personal default. Global
routing requires an authorized default-home change. Codex's
[adapter](adapter-codex.md) identifies its global path and overrides.
Preserve unrelated instructions and every byte outside the AIOS marker pair.
Record the pre-edit hash, reread before patching and make identical replay a
no-op. Multiple/malformed blocks, a changed source or conflicting home require
reconciliation. Do not change other apps or store owner data in plugin caches.

Use the [context pointer](../../osm-data-context/assets/bridge.md) with the chosen
provider and exact guide URL/path. Verify that guide before activation. Notion
is the recommended starting point; a configured alternative remains selected.
No local mirror or AIOS_FORMAT is required for document/vault homes.
For file context, use the [file bridge](../../../docs/legacy-file-home/bridge.md) with the literal
physical owner path. Resolve an established home first, defaulting to ~/.AIOS.
AIOS.md plus supported AIOS_FORMAT identify even a Git-backed home; unsupported
or malformed formats remain read-only.

Verify owner routing and independent repository isolation in fresh tasks.
Never place owner-context preload in parent/owner-home AGENTS or overrides.
A pointer supplies no account access or permission grant.

Selected personal-skill setup or home moves use Manage Skills'
[personal skill lifecycle](../../osm-manage-skills/references/owner-skills.md).
Do not repeat that procedure or register personal skills merely to install OSM.
