# OSM:log

Run before handing back a completed piece of substantive work, or when the
user asks in ordinary language to save a decision, correction or other learning.
A chat can continue after Log. Repeated checkpoints review only evidence added
since the last verified checkpoint.
The lead retains Log in delegated work. Dreaming uses its own run result.

Before a checkpoint write, follow [Writing for a person](../osm-manage-data-context/references/human-output.md).

1. Review the useful result, decisions and explicit corrections since that
   checkpoint. Retain what would help the next relevant session act. Leave
   routinely retrievable facts, work artifacts and live status at their
   existing sources.
   Check source-specific retention as well as destination write authority.
   Source-only or restricted records stay in their system, even when the
   agent may read them. Do not copy them into Notion, a log, a worker brief
   or a paraphrased summary to bypass that rule. Save only the permitted
   route, decision or learning, with permitted evidence.
2. Resolve the target and effective write authority from the current task. Use
   the home verified for that scope, even when the host has a different
   personal default. Without a verified destination and authority, keep a
   concrete proposed update with the task. Leave unrelated project work local.
3. Use [Manage Data & Context](../osm-manage-data-context/index.md) for intake,
   record identity and verified writes. Save supported lasting context
   automatically within verified authority. Hold an uncertain or conflicting
   change as pending. Skip routine or unchanged material.
4. Use the shared [progress and retry rules](../osm-manage-data-context/references/activity.md)
   so an uncertain write is read back before any retry. A later Log or Dreaming
   run reconciles the same learning against the same existing topic.
5. Correct a verified logging or context error at this checkpoint. Use the shared
   [repair rules](../osm-manage-data-context/references/activity.md#repair-in-the-current-session)
   to verify the correction and leave a short note for Dreaming.

If anything lasting was saved or held, name it and its destination briefly
with the result. Leave an ordinary no-change checkpoint quiet.
