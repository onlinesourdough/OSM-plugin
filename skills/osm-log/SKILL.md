# OSM:log

Run before handing back a completed piece of substantive work, when the
user asks in ordinary language to save a decision, correction or other learning,
or before this session creates or revises any Notion page or database row.
A chat can continue after Log. Repeated checkpoints review only evidence added
since the last verified checkpoint.
The lead retains Log in delegated work. Dreaming uses its own run result.

When Notion is connected, these writing rules apply to every page the task
authorizes, including pages outside the context home. A checkpoint in the
context home is one case, not the only one.

For a task-authorized page that is not a context checkpoint, follow step 3
and step 5 only. Write the page where the task already places it. Steps 1, 2,
4 and 6 apply to a home checkpoint only.

1. On a home checkpoint, review the useful result, decisions and explicit
   corrections since that checkpoint. Retain what would help the next relevant
   session act. Leave routinely retrievable facts, work artifacts and live
   status at their existing sources.
   Check source-specific retention as well as destination write authority.
   Source-only or restricted records stay in their system, even when the
   agent may read them. Do not copy them into Notion, a log, a worker brief
   or a paraphrased summary to bypass that rule. Save only the permitted
   route, decision or learning, with permitted evidence.
2. On a home checkpoint, resolve the target and effective write authority from
   the current task. Use the home verified for that scope, even when the host
   has a different personal default. Without a verified destination and
   authority, keep a concrete proposed update with the task. Leave unrelated
   project work local.
3. Before creating or revising any authorized page, follow
   [Writing for a person](../osm-manage-data-context/references/human-output.md).
   Read the target database schema and properties, its template if one exists,
   and one or two recent comparable rows or pages. Mirror their structure,
   names, property use and length. Write the page and the handback so a person
   can use them on a first reading.
4. On a home checkpoint, use
   [Manage Data & Context](../osm-manage-data-context/index.md) for intake,
   record identity and verified writes. Save supported lasting context
   automatically within verified authority. Hold an uncertain or conflicting
   change as pending. Skip routine or unchanged material.
5. Read an uncertain write back before any retry, using the shared
   [progress and retry rules](../osm-manage-data-context/references/activity.md).
   On a home checkpoint, a later Log or Dreaming run reconciles the same
   learning against the same existing topic.
6. On a home checkpoint, correct a verified logging or context error. Use the
   shared
   [repair rules](../osm-manage-data-context/references/activity.md#repair-in-the-current-session)
   to verify the correction and leave a short note for Dreaming.

If anything lasting was saved or held, name it and its destination briefly
with the result. Leave an ordinary no-change checkpoint quiet.
