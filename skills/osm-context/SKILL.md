# OSM:context

Own the context-home contract and select one provider route. The host's short
instruction points to the chosen context entry; its short guide holds the
owner's destinations, Spaces and working policy. OSM supplies shared methods,
not company data. A skill guides the running agent; it is not a background sync.
The [Context Architecture](references/architecture.md) is the one root, storage,
access and readiness contract; "guide" in these references means its root entry.
OSM is an AI-assisted method and framework for solo founders and small teams.
Data and context are its two foundation parts, and skills sit inside context.
Notion is the central reference setup, and an explicitly retained compatible home
stays supported. Core OSM establishes general business goals, audiences, offers
and voice. Content is an optional companion, set up only when selected; upkeep
can maintain an existing Content collection without it, and Content's own
workflows stay as they are. The owner's recorded
[write policy](references/architecture.md#home-write-policy) decides what
Context upkeep may write, and one current record per topic keeps context short.

Use the current selected home or verified host pointer. Consult
[provider selection](references/providers.md) only when unresolved; carry the
choice through the operation without reloading selection.
Resolve the home within this task's owner/client scope. An explicitly selected
customer home governs that task; an unrelated personal host pointer is neither
a conflict nor a migration target. Do not replace the user's default while
setting up a client. Persistent routing changes only at the intended scope.
Notion is the recommended starting point for solo founders, business leaders
and small teams. Preserve an established alternative unless a move is requested.
An installed connector alone never selects a home or authorizes migration.
[Setup](../osm-setup/SKILL.md) leads new or resumed onboarding. If already
running Setup, continue the selected provider procedure below without restarting
it. Installation alone does not connect or configure a home. Context owns the
home contract and its ongoing use.

For an unresolved home design, a move or a structural audit, apply the
[home contract](references/home-contract.md). A concrete provider setup already
implements that contract; direct setup with an accepted provider need not load
this wrapper again. Adapt existing work instead of generating empty documents. Keep actual IDs, fields,
templates and source responsibilities in the owner's guide, outside this plugin.

| Requested work | Procedure owner |
| --- | --- |
| Read relevant context | Fetch the root entry once per session. Use [Notion operating](references/notion/operating.md), managed-file AIOS.md and its relevant routes, or the [existing-home procedure](references/existing-home.md) for another home |
| Set up or move the home | [Notion setup](references/notion/setup.md), [managed-file Setup](../osm-setup/SKILL.md) or [existing-home adaptation](references/existing-home.md); Setup also owns native installation |
| Save a durable fact, decision or correction | [Maintain Context](../osm-maintain-context/SKILL.md) using the resolved provider; unchanged information produces no write |
| Inspect context health | [Check](../osm-check/SKILL.md) using the home contract and selected provider checks; read-only unless repair is separately authorized |
| Create or change a personal/team skill | [Manage Skills](../osm-manage-skills/SKILL.md); preserve its canonical body, references and actual discovery mechanism |

For a provider outage or uncertain destination, hold dependent changes and
report the exact gap. Do not fall back to another provider or an old local home.
Continue unrelated work from its accepted inputs. A general question or an
independent repository task needs no owner-context preload.

For authorized route changes, reconcile available [dashboard links](references/panel-links.md).
At completion, verify the affected records/routes and distinguish setup,
successful retrieval, actual skill use and future operation. Reuse the current
task's authority; a guide cannot grant permissions by its content, except the
root's recorded `write_policy`. Report bounded
observations, unsaved work and remaining capability gaps without claiming every
provider is implemented or tested.
