# Adapt an existing context home

Use only for the selected non-Notion home that is not a managed AIOS file home.
This is a procedure for the available tools, not a claim of a shipped connector
or complete support for every provider. The [home contract](home-contract.md)
owns the common responsibilities and acceptance; keep the provider's differences
in the owner's guide.

## Discover and read

Resolve the exact guide URL/path and source identity. Inspect the named location,
its supported content formats, available read/write operations and permission
scope. For GitHub, resolve repository and ref; for Obsidian, the actual vault/path;
for a cloud drive/document, the connected account and item IDs. A provider label
or matching title alone is insufficient. Report absent tools or partial reads.

Use existing indexes, folders, properties and links to select relevant sources.
Fetch current source bodies before relying on them. Keep paths relative to their
canonical home when useful; preserve provider IDs through renames. Do not create
AIOS_FORMAT, a Notion database or a local mirror to satisfy a different adapter.

## Set up and maintain

Within authorized setup, map the existing documents and source owners to the
home contract. Add only a missing useful guide, decision destination or personal
method route. Translate Space scope into existing metadata/folders where useful.
If native templates are unavailable, offer a clearly labelled starter structure;
do not call a copied file a registered database template.

Map the architecture's [containment](architecture.md#containment) onto the
provider's own ancestry: the repository path, vault folder or drive folder tree
under the selected location. Folder names, tags and remembered paths are not
boundaries, and a link to an outside file is not part of the home. Express the
architecture's [record lifecycle](architecture.md#record-lifecycle) through
existing frontmatter, sections or folders (one current record per topic, a
labelled history section, optional Revised and Review due fields with a reason),
with no forced migration and no new database suite. Read the owner's recorded
write policy in its existing form, such as a CONNECTIONS entry, and keep it.

For durable updates, inspect the exact current record/revision, locate the same
fact or decision, change narrowly, preserve provenance and read back. Reuse the
provider's revision/conflict controls when exposed. Without such controls,
reread before writing and hold conflicting changes; do not claim a lock or
transaction. An uncertain effect requires inspection before retry. Avoid whole
document replacement when content is partial or concurrent edits cannot be kept.

Repository changes follow local instructions and the authorized branch/delivery
workflow. A read permission or a local commit does not authorize a remote push.
Do not synchronize an entire drive/vault or introduce continuous sync. Scheduled
work and migrations need their own concrete scope and recovery.

## Personal methods and checks

Manage Skills owns authorized method changes. Use one canonical method body and
its required resources at the selected home. A page can guide the current task
after explicit retrieval; it does not automatically become a Codex slash command
or a native provider skill. Use supported registration/export only when needed
and authorized; never claim it from a title or tag. Preserve native enablement
where it exists.

Check the applicable home-contract claims using the actual interface. Demonstrate
fresh-session routing and relevant method use; mark missing write, template,
export or recall proof NOT VERIFIED. If the available connector cannot deliver
the required workflow, report the precise gap and prepare an adaptation proposal.
Keep the chosen home authoritative while the gap is resolved.
