# Notion setup acceptance

Report PASS, FAIL or NOT VERIFIED with concrete observations. Read-only Check
does not create test data; onboarding authority may include a clearly scoped
test artifact. Do not confuse these observations with future reliability.

| Claim | Required observation |
| --- | --- |
| Recovery | Verified backup bytes and actual restore inspection; exact previous plugin, bridge and owned registrations |
| Source identity | Correct workspace, guide, database schemas and relevant access; preserve same-title decoys |
| Connection | Native app status and selected-page read are separate observations. Cover disconnected, connected, inaccessible page, read-only and resumed setup without resetting auth, writing permission probes or duplicating the home |
| Import | Source/destination map, provenance/dates, every required skill file accounted for, no lost unknown blocks |
| Native skill | Readback confirms native designation, current body and required resources |
| Navigation | The existing home opens the chosen full-page databases; useful views work, original Docs templates/content remain and retired view routes are repaired |
| Dashboard | After a route change, a chat refresh shows the model's actual groups with the snapshot's save time and source revision; earlier saved links stay as More links; stale, partial and denied states are honest. Source, fixture and live app evidence stay separate |
| Schema and templates | Apply the [schema contract](schema-and-templates.md): consistent Space names/hierarchy, explained fields, retained IDs, no duplicate logical keys or broken relations; native templates instantiate their intended defaults without fixed keys or dates; verify actual skill designation separately |
| Team skills | Personal/Team audience, accountable owner and change authority resolve independently of Space; test retrieval with the intended user identity; filtered views are not permissions. Solo setup creates no empty team database. Private references are not shared by relabeling |
| Idempotence | Repeat discovery/reconciliation selects the same IDs and leaves unchanged pages unedited; a changed destination is preserved |
| New home and same-title guide | A blank workspace gets only useful approved destinations: the model as a page in a private document database (an approved existing Docs destination where suitable), an optional OSM home linking to it, and the selected About/Memory/Skills and optional Soul, with placement read back. An existing guide titled AIOS or kept as an ordinary page is reused by ID where it is, never duplicated or moved for placement alone |
| Setup recipe and model revision | The adopted upstream setup version and local deviations are recorded apart from the model's revision; a newer upstream version is reconciled without overwriting customized rules or resetting the setup |
| Native databases and templates | A needed Tasks, Projects or Skills database uses the supported native type (never with a custom schema), and its identity and canonical properties are read back. Existing renamed, translated or same-title decoy databases resolve by ID; resemblance alone is not called native type. One authorized template application shows its populated defaults, not only a success response |
| Native Tasks and empty My Tasks | An already native source with no selected personal source is fixed by selecting it, with no new database or conversion. Unassigned or filtered rows are explained; only intended owner or status changes happen; trashed, completed and archived records keep their meaning; the same records then appear in My Tasks with their IDs and fields |
| Populated conversion | Only when native type is really missing and a supported in-place path exists: a before snapshot, then IDs, rows, fields, relations, bodies, status groups, views and access verified after; otherwise the source is kept and the limit stated |
| Meetings and plans | The default meeting-notes destination is reused and no `meetings` type is sent. Missing meeting tools, AI entitlements or other plan limits are reported where relevant, and ordinary notes and the rest of setup stay usable without an upgrade |
| Connection and discovery | On the actual execution host: a working official or direct connection is reused with no new config, server or sign-in on replay; a missing discovery tool is named with ordinary reads still working and the direct hosted path offered within authority; pending or denied sign-in, an exposed but failing tool and an unrefreshed chat are each reported with the exact next action; an empty discovery result is told apart from enabled skills; nothing is enabled silently |
| Skills and access | Designation, per-surface enablement, discovery and relevant use are reported separately; a coworker without access to a skill's source page is not given access by enablement, and the approved fallback is shown when discovery is absent |
| Memory identity | Existing custom Memory plus an empty native alias returns the real records and creates no competing store |
| Memory provenance | Save, then a correction by another client: readback keeps the original Source, changes Last updated by, preserves evidence and dates, adds no duplicate topic and invents no unknown provenance |
| Schema transition | Renaming or retyping a populated provenance field uses a before snapshot and readback after each step; values, counts, relations and files survive, and recovery is shown |
| Missing capability | An absent native save, search, enablement or discovery tool, partial access or a failed write gives the exact limitation and the approved fallback, with no false completion, invented call or broader permission |
| Native skills | Designation, the selected account's enablement and references are read back. Enabled discovery is verified where exposed; otherwise the exact-page fallback is reported as a fallback |
| Selective context | An owner task reads the model once, plus Soul only when the model lists it as standing context, then only the needed sources, without a second full policy read |
| Second agent | A fresh second supported agent follows its own effective pointer to the same model without OSM, applies a correction and creates no duplicate; host and connector revisions are recorded |
| Work systems | A real existing task is read and an authorized update lands on that record; its live status is not copied into Memory or the model |
| About and policy | An unchanged maintenance pass writes nothing; a material About correction changes only that summary; a method or policy change reaches its owner |
| Messy existing home | Reuse suitable Docs/native Skills/Memory by identity, add only missing destinations, preserve unclassified records and same-title decoys, and prove the first chosen workflow without broad migration |
| First setup | OSM Setup leads the plain-language request through one provider procedure without repeated invocation. Missing access gets a concrete sign-in/access action. The owner supplies decisions, not technical configuration. Verify the filled entry before setting the pointer at the correct scope; an undecided task stays pending |
| Business coverage | Offers, Demand and Operations resolve to inspected sources or explicit gaps. Resolve gaps needed for the first task; preserve others without invented facts, compulsory topic documents or skills. Existing methods retain their resources; Memory can start empty |
| Fresh use | New native session reads the configured guide and relevant current sources, returns a sourced answer and uses a personal skill correctly |
| Freshness | A controlled change in the test source is visible in a second retrieval; no local shadow truth |
| Isolation | Independent repository task follows its local instructions without reading owner context |
| Read-only Check | Context Check detects a controlled route defect and reports its repair owner without changing anything |
| Failure | Unavailable guide or required file produces an explicit gap without fallback/mutation |
| Activation | Native package/version and enabled selection read back; prior competing route disabled reversibly |
| Maintenance | One authorized task-time correction reaches its existing canonical record; no write or duplicate on unchanged replay |
| Optional schedule | Only when explicitly requested: exact native schedule readback and one scoped run; distinguish future delivery from observed execution |
| Rollback | Owned pointer/selection/links restored in a rehearsal; unrelated and subsequent edits preserved; Notion work retained |

For shared source changes run the repository's affected package, link, version
and footprint checks. They do not replace live Notion or native-session proof.
Report UI activation, API discovery, execution and later-session recall as
separate evidence. An individual onboarding needs one useful workflow, not
every row here.
Report personal-skill use as not applicable when the selected task needs none;
verify existing skill migrations separately. Report structure readiness and
actual first-task/correction proof separately so an empty setup cannot pass as
a working business workflow. Repeat setup must preserve local page wording and
agreements as well as record identities.
