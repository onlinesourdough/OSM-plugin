# A useful context home

This contract describes responsibilities, not a mandatory schema. Use it for
setup, moves and structural audits. Ordinary tasks read only relevant routes.

| Responsibility | Record in the owner's guide |
| --- | --- |
| Identity and access | Exact provider, account/workspace or repository/path; verified connection and boundaries |
| Read/write policy | When to read the guide, what to retrieve, what may be written where, and known capability limits |
| Collaboration and profile | Optional owner-selected Soul (about 150 words) and a short source-linked About |
| Knowledge and work | Where maintained facts, original references and deliverables belong; which system owns each, including live task status |
| Spaces | Optional: business, brand, sub-brand, team, life or continuing-area scopes already in use, what is common and what is scope-specific, and useful parent/child relationships |
| Setup baseline | The provider setup recipe and version adopted, and local deviations; kept apart from the guide's own revision |
| Memory | One canonical store of durable facts, decisions, corrections and lessons, with reasons, provenance, actual source dates and uncertainty |
| Personal methods | Where to discover the owner's reusable skills and their supporting resources |
| Maintenance and recovery | Authorized write scope, identity/deduplication rule, readback, correction handling and recoverable prior route |

The guide (in Notion, the AI Operating Model) is the complete, user-owned
contract: another connected agent can read and maintain the home from it
without installing OSM. The host keeps only a short pointer to it. A home page
that gathers links is navigation, not a second guide or route map, and needs no
reorganization of where sources live.

One context home can cover multiple Spaces. Projects keep their native workspaces;
they need not become new owner homes. Express Spaces with the provider's useful
properties, relations, folders or routes. Reuse existing concepts. Add a separate
registry only when maintaining the hierarchy needs it. Scope labels are not
access control. Load shared and parent context only when relevant.

Generate or adapt a short owner guide and useful entry templates from verified
sources and accepted choices. Do not manufacture company facts, empty departments
or a parallel truth store. Provider-specific properties and templates belong in
the selected adapter; actual values and IDs belong in the customer's workspace.
Use [the thin host pointer](../assets/bridge.md) through the selected native
[adapter](../../osm-setup/references/adapters.md). An existing managed file
bridge can continue using its exact supported root.

People should be able to find and edit their work normally. The agent should
select metadata or an index first, then read only the relevant bodies. The
context home can route to several source systems without centralizing all data.
Links and copied summaries are not live synchronization.

## Maintenance and evidence

For business setup or a foundation audit, use the [business coverage check](business-context.md).
Map Offers, Demand and Operations to useful sources or explicit gaps. This does
not require a document for each topic, a personal skill or prefilled Memory.

At meaningful decisions, corrections and task checkpoints, use Maintain Context
under current-task or standing write authority. Reconcile identity and meaning
before creating; preserve dates, reasons, exclusions and useful history. No new
durable knowledge means no write. Missing access leaves an explicit unsaved
change. Facts maintenance does not change shared/personal skills or approved
policy. Those have their own authorized lifecycle.

For setup or a material change, verify the selected scope:

- Actual source identity, usable destinations and intelligible Space navigation.
- Preserved existing content and working native templates where supported.
- Exact source references and complete personal-method resources.
- A fresh session retrieves the relevant current fact and selected method.
- An authorized correction is visible on another retrieval; unchanged replay
  produces no duplicate or routine record.
- A missing guide/source is reported without silently changing homes.
- An independent repository task does not preload personal/business context.
- Recovery preserves subsequent edits and the original source responsibilities.

A read-only audit reports PASS, FAIL or NOT VERIFIED for applicable claims; it
does not instantiate templates or repair data. Real setup tests require their
existing task authority. Source checks, synthetic fixtures and live provider
tests remain distinct. A schedule is optional and needs an explicit request;
neither this contract nor a skill guarantees freshness between tasks.
