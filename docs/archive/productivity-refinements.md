# Productivity skill refinements: 0.13.0

Baseline: `v0.12.0` / `73c44fa94e4e698d10be51ff52ba3b2d5a107284`.

## Accepted result

Keep AIOS business-first with productivity built in. Software & Defense Factory
is an independent product with its own software/security skills and operation;
it requires no AIOS runtime or installed method package. General AIOS work still
uses its existing proportional quality, verification and safety criteria.

The authorized change covers implementation, review, pilot release and the
existing Codex installation, plus a handoff of this boundary to the factory
task. Preserve 24 canonical skills, names, owner formats and unrelated methods.
Owner data and other harness registrations are outside the installation scope.

| Method | Accepted delta |
| --- | --- |
| Write Code 1.0.2 | Distinguish shared behavior from superficial similarity; refactor affected callers incrementally while preserving their policies and keeping small scripts simple |
| Design 1.2.0 | Own a conditional before/after reference with an identified baseline, comparable views and evidence appropriate to the claim |
| Review Design 1.2.0 | Apply that same reference to selected comparisons and assess improvement, regressions and limitations against the brief |

| OpenPencil Workbench 1.0.2 | Check fresh status and the rendered document on start/resume and live handback; use one built-in Codex browser tab and preserve recoverable work during diagnosis |

Before/after capture uses available tools and project/task evidence. No recorder,
upload endpoint, PR automation, testing platform or external review service is
introduced. Factory-specific workflows remain with the factory.

The owner added OpenPencil readiness and duplicate-browser handling before
release. The inspected task used a separate Playwright browser and then opened
the same editor in Codex. The existing helper already offers live status and
asset/document checks; the method now makes their use and actual canvas
inspection explicit. No runtime patch or external browser installation is needed.

## Verification scope

Run package/link/release validation against the baseline, documentation,
skill-version, footprint, layout and continuity checks. The new reference is
loaded only for selected visual comparisons. Report its bytes separately from
default skill reads; file sizes do not measure model cost or quality.

A bounded native probe exercises actual prose rewriting and decisions about
simple code, shared behavior and visual evidence. It must distinguish claims
from observations and preserve the task's authority. This is not a full browser
capture, end-to-end factory test, cross-model comparison or benchmark.

Independent review binds the final source tree and actual proof before release.
Native installation verification then checks the reviewed release identity,
installed package and fresh-session discovery. Reusing the task's existing
model and available native controls requires no settings or model change.

## Observations: 2026-09-22

- Package, link, release-tag and per-skill baseline validation passed, as did
  seven documentation cases, seven skill-version cases, layout and continuity
  rehearsals and whitespace checks. No validation ceiling or fixture was relaxed.
- The first Write Code draft exceeded the existing worker-build footprint ceiling
  by 253 bytes. Removing repeated wording brought the final skill to 5,114 bytes,
  only 151 bytes above baseline. The selected worker-build path is 38,028 bytes
  against its unchanged 38,099-byte ceiling. Discovery metadata plus the observed
  bridge remains 4,465 bytes. The conditional comparison reference adds 2,552
  bytes when selected; all skill bodies remain below 8,192 bytes. These are
  static file/read counts, not measured quality or runtime savings.
- Codex CLI 0.155.1 with the existing configured GPT-6 Astra/xhigh route produced
  two actual prose rewrites preserving uncertainty, a condition, an exact heading
  and command, while replacing inflated claims with the supplied concrete fact.
- Four decision cases kept the one-off script simple, preserved distinct caller
  policies and a useful single-use adapter, rejected an incomparable visual pair
  as evidence of performance/usability, and declined to invent a new slide's
  baseline. The two code cases were rerun after final wording compression;
  the other cases' source was unchanged. Both native runs completed read-only.
- The [sanitized prompts, outputs and final source hashes](../evidence/productivity-refinements-probe.json)
  make those observations inspectable. Prompts explicitly selected candidate
  instructions, so they do not establish automatic discovery. Proposed checks
  and captures were not executed. Installation and release are verified later
  against this reviewed source; no such observation is claimed here.
- OpenPencil's six existing helper fixtures passed using their synthetic daemon,
  including status/logs, no OS opener, source isolation and cleanup. The helper
  script is unchanged. An additional [five-case native decision probe](../evidence/openpencil-readiness-probe.json)
  rejected stopped-but-exit-zero readiness, treated a blank canvas as unverified,
  preserved unsaved work before recovery, reused the built-in browser without
  launching Chrome, and required the current session URL at handback. The probe
  executed none of those browser/runtime actions. Incident inspection confirmed
  the earlier duplicate-browser route; the latest reported runtime error was not
  available from the task reader. This is a method correction, not a claim to
  have reproduced or repaired that unobserved runtime failure. Package,
  documentation and footprint checks passed again with this addition.
