# Shared lifecycle and selective delegation

Accepted change, 2026-09-10. The owner requested one shared Spec, Build,
Review and Ship implementation in AIOS, specialist-only repository skills,
direct tasks without mandatory lead/worker ceremony, updates across relevant
repositories and seeds, a release, and local adoption.

The current task owns the cross-repository contract and native goal. Each
repository remains canonical for its local requirements and evidence. Work is
performed sequentially in isolated repository worktrees: these instruction
changes share one decision and do not benefit from repeated worker discovery.
The native plan is the only live requirements list. Existing dirty changes,
active designs, unrelated application work and local-only privacy boundaries
are preserved. Repository delivery and the AIOS release/update are authorized
by the request; unrelated product deployment or publication is outside scope.

## Accepted contract

- The 15 AIOS product skills remain the single shared source. Spec, Build,
  Review and Ship work with repository AGENTS and accepted inputs without
  loading personal owner context. Technology selection and generic accumulated
  drift review become conditional references of Spec and Review.
- Existing generic Project skills and tracking copies are removed after
  preserving any real repository-specific constraints in their local owner.
  Seeds emit only local instructions and specialist skill space. Domain review
  and domain audit methods remain independent specialist responsibilities.
- Continuing the current task is the default, including substantial repository
  work. Delegation requires a bounded deliverable and a concrete benefit after
  context, coordination, review and retry cost. An explicit new-task request
  remains subject to its harness tool; root/authority and one writer still apply.
- Source/link/package validation, generated-project fixtures and a bounded
  native routing/discovery smoke verify the change. Report instruction byte
  counts separately from actual usage; no universal performance claim.
- Review binds the final candidate. Release AIOS 0.4.0 through the existing
  repository, then adopt it through supported native package controls. Old
  loaded sessions are distinguished from fresh-session discovery.

## Recovery

Repository base commits and scoped local change backups are retained outside
product payloads. Do not overwrite concurrent edits or publish unrelated dirty
work. Revert the reviewed migration commit for source recovery; use the prior
reviewed AIOS v0.3.5 registration for package rollback. Neither path restores
user artifacts or rewrites their history. Author checks and native observations
are recorded separately in the verification evidence for this change.
