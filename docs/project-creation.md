# Project creation: 0.17.0

Historical record. AIOS 0.28.0 later retired Project Foundation; see the
[current note](project-foundation.md#0280-retired-in-favor-of-factory-foundation).

Baseline: `v0.16.0` / `082cfe3a9168c06526f9c53f309687a92f3a551b`.

## Accepted boundary

A project can be content, learning, research, business work or software. Its
initial useful result can be a sensible location, a simple working structure
and enough context to continue. Git, GitHub and a repository template are
choices for the work, not the definition of a project or a required AIOS registry.

Create Project 3.0.0 owns that setup. Its former default repository/template
contract becomes the conditional repository-seed reference. Verified acquisition,
fixed clean seed, transfer/recovery, preserved product licensing and the shared
software engineering/document criteria remain there. Existing work is preserved
and is never reseeded. The major skill version records the changed default.

Project Foundation 1.1.1 retains its distinct responsibility for software
engineering readiness in new and existing projects. General folder setup and a
template receipt do not prove an application, deployment or execution host ready.
The description and entrypoint now make the software boundary explicit.

Create System is retired, including its native display metadata and active
callers. Reusable methods use Manage Skills; separately maintained solutions
retain their own ordinary project lifecycle. The legacy route map redirects
the old name without shipping a second discoverable skill. Immutable `v0.16.0`
retains the earlier source for recovery. No existing project or specialist is
deleted, archived, relocated or regenerated by this package change.

Agentic Systems is a separate work environment and method. AIOS can support software
work directly; selecting Agentic Systems remains a separate operator action as in the
existing 0.14.1 boundary. The package installs no Agentic Systems runtime, shared
credentials, scheduler or hooks. Human collaboration, unattended execution and
the required technical controls are distinct questions; actual protection stays
with the selected harness/environment and the project's own safeguards.

## Verification and limits

The package checks retain the shared foundation links through the conditional
seed reference, complete legacy mapping, per-skill versions and native identity.
The historical context-footprint baseline remains unchanged. Source checks,
bounded native behavior, independent review and release/install readback are
separate evidence; the release PR records the final subject and observed checks.

This change does not qualify a Agentic Systems installation, enable hooks, deploy an
application or prove all harness behavior. Native removal of the retired skill
requires adoption of the released package in each selected app; an update in
one app does not update another. Owner format and owner-data migration are
outside this package change.
